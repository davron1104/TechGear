Техническое задание — интернет-магазин компьютерной техники и аксессуаров
1. Общая информация
1.1. Название проекта

TechGear — небольшой интернет-магазин компьютерной техники и аксессуаров.

1.2. Тематика

Магазин специализируется на продаже:

клавиатур;
мышей;
гарнитур;
мониторов;
накопителей;
компьютерных аксессуаров.
1.3. Цель проекта

Разработать полноценный небольшой интернет-магазин с каталогом товаров, корзиной, регистрацией пользователей, личным кабинетом, оформлением заказов и административной панелью.

Проект должен демонстрировать основные современные подходы full-stack веб-разработки и иметь архитектуру, позволяющую в дальнейшем расширять функциональность.

2. Роли пользователей

В системе предусмотрены три состояния пользователя.

2.1. Гость

Неавторизованный посетитель может:

просматривать каталог;
просматривать категории;
открывать страницы товаров;
добавлять товары в корзину;
изменять количество товаров в корзине;
удалять товары из корзины;
оформить заказ.
2.2. Покупатель

Зарегистрированный пользователь дополнительно может:

входить в аккаунт;
выходить из аккаунта;
редактировать данные профиля;
просматривать историю своих заказов;
просматривать отдельный заказ;
сохранять корзину между сессиями;
восстанавливать доступ к аккаунту.

Покупатель не имеет доступа к административной панели.

2.3. Администратор

Администратор имеет доступ к административной панели и может:

просматривать товары;
создавать товары;
редактировать товары;
удалять товары;
управлять категориями;
просматривать заказы;
изменять статус заказа;
просматривать информацию о покупателях, связанную с заказами.
3. Категории товаров

На первом этапе используются следующие категории:

Клавиатуры
Мыши
Гарнитуры
Мониторы
Накопители
Аксессуары

Категории должны храниться в базе данных и управляться через административную панель.

4. Товар

Каждый товар содержит:

уникальный идентификатор;
название;
категорию;
цену;
изображение;
краткое описание;
подробное описание;
количество на складе;
характеристики;
дату создания;
дату последнего изменения.
4.1. Характеристики

Характеристики товара являются динамическими.

Разные категории имеют разные характеристики.

Например, для мыши:
DPI: 26000
Подключение: Wireless
Вес: 72 г
Количество кнопок: 6
Для монитора:
Диагональ: 27"
Разрешение: 2560×1440
Частота: 165 Hz
Тип матрицы: IPS
Администратор может добавлять необходимое количество характеристик при создании или редактировании товара.

5. Каталог

Главная страница содержит каталог товаров.

Карточка товара отображает:

изображение;
название;
категорию;
цену;
информацию о наличии;
кнопку добавления в корзину.

Если товара нет в наличии, вместо возможности покупки отображается соответствующий статус.

Каталог должен поддерживать фильтрацию по категориям.

6. Страница товара

Для каждого товара существует отдельная страница.

Она содержит:

большое изображение;
название;
категорию;
цену;
наличие;
краткое описание;
подробное описание;
характеристики;
выбор количества;
кнопку добавления в корзину.

Если товара недостаточно на складе, пользователь не может добавить количество, превышающее доступный остаток.

7. Корзина

Корзина является виджетом, а не отдельной страницей.

При нажатии на иконку корзины открывается боковая панель или адаптированный мобильный вариант виджета.

Корзина содержит:

список товаров;
изображение товара;
название;
цену;
количество;
кнопки изменения количества;
удаление товара;
итоговую стоимость;
кнопку оформления заказа.
7.1. Корзина гостя

Для неавторизованного пользователя корзина сохраняется локально в браузере.

7.2. Корзина покупателя

Для авторизованного пользователя корзина хранится в базе данных и привязана к его аккаунту.

При выходе из аккаунта корзина не удаляется.

После повторной авторизации корзина восстанавливается.

7.3. Объединение корзин

Если у гостя уже есть товары в локальной корзине, а после авторизации у его аккаунта также существует сохранённая корзина, система объединяет их.

При объединении обязательно проверяется актуальное наличие товаров.

8. Оформление заказа

Покупатель может завершить покупки, отправив заявку с товарами из корзины.

Форма оформления содержит:

имя;
фамилию;
email;
номер телефона;
комментарий к заказу.

Для авторизованного пользователя данные профиля подставляются автоматически и могут быть отредактированы перед отправкой.

После успешной отправки создаётся заказ.

Корзина после успешного создания заказа очищается.

9. Заказы

Каждый заказ содержит:

уникальный идентификатор;
пользователя;
дату создания;
статус;
контактные данные покупателя;
комментарий;
состав заказа;
итоговую стоимость.

Статусы заказа:

NEW
CONFIRMED
COMPLETED
CANCELLED
9.1. Состав заказа

Каждая позиция заказа содержит:

товар;
название товара на момент оформления;
цену товара на момент оформления;
количество;
итоговую стоимость позиции.

Название и цена сохраняются непосредственно в заказе, чтобы изменение товара в будущем не изменило историю старых заказов.

10. Изменение количества товара и отмена заказов

Количество товара на складе не уменьшается при создании заявки.

Алгоритм изменения остатков:
Покупатель создаёт заказ
        ↓
Заказ получает статус NEW
        ↓
Количество товара НЕ изменяется
        ↓
Администратор проверяет заказ
        ↓
Подтверждает заказ
        ↓
Система повторно проверяет остатки
        ↓
Количество товара уменьшается
        ↓
Заказ получает статус CONFIRMED

Если товара недостаточно, заказ не может быть подтверждён. Администратор получает сообщение о недостаточном количестве товара.

Правила изменения статусов и отмены заказов:
- Статус NEW (Новый):
  - Покупатель может самостоятельно отменить свой заказ (это меняет статус заказа на CANCELLED, но не удаляет его физически из базы данных).
  - Администратор может подтвердить заказ (перевод в статус CONFIRMED со списанием остатков) или отменить его (перевод в CANCELLED).
  - Так как остатки товара уменьшаются только при переходе заказа из NEW в CONFIRMED, при отмене заказа в статусе NEW остаток товара на складе не изменяется.
- Статус CONFIRMED (Подтверждён):
  - Покупатель не имеет возможности отменить или изменить заказ.
  - Администратор может перевести заказ в статус COMPLETED или CANCELLED. При отмене подтверждённого заказа остаток товара на складе не изменяется.
- Статус COMPLETED (Выполнен):
  - Покупатель не может отменить заказ. Заказ считается успешно завершённым.
- Статус CANCELLED (Отменён):
  - Заказ считается окончательно отменённым.

11. Регистрация и авторизация
11.1. Регистрация

Страница:

/register

Поля:

имя;
email;
пароль;
подтверждение пароля.

Email должен быть уникальным.

Пароли не хранятся в открытом виде — в базе хранится безопасный хеш пароля.

11.2. Авторизация

Страница:

/login

Содержит:

email;
пароль;
кнопку входа;
ссылку на регистрацию;
ссылку восстановления пароля.
11.3. Выход

Авторизованный пользователь может выйти из аккаунта.

Корзина пользователя при этом сохраняется.

11.4. Восстановление пароля

В первой версии используется восстановление доступа к аккаунту через email:
- Пользователь запрашивает ссылку сброса пароля, указав свой email.
- Система генерирует уникальный одноразовый токен с ограниченным сроком действия (1 час) и сохраняет его в базе данных (сущность `PasswordResetToken`).
- Ссылка на форму установки нового пароля, содержащая токен, отправляется пользователю на указанный email.
- При переходе по ссылке пользователь вводит новый безопасный пароль. После успешной валидации токена система обновляет хэш пароля пользователя, а использованный токен удаляется из базы данных.

Telegram-восстановление не является обязательной частью MVP.

12. Личный кабинет

Страница:

/account
Профиль

Пользователь может:

просматривать свои данные;
изменять имя;
изменять фамилию;
изменять email;
изменять телефон.
История заказов

Пользователь видит только собственные заказы.

Для каждого заказа отображаются:

номер;
дата;
итоговая стоимость;
статус.

При открытии заказа пользователь видит полный состав заказа.

Покупатель не может изменять свои заказы, но может отменить свой собственный заказ, пока он находится в статусе NEW. Отмена заказа меняет его статус на CANCELLED (без физического удаления из базы данных). В других статусах (CONFIRMED, COMPLETED, CANCELLED) отмена или изменение заказа покупателем невозможны.

13. Административная панель

Административная часть доступна только пользователям с ролью администратора.

Основные разделы:

/admin
/admin/products
/admin/categories
/admin/orders
14. Управление товарами

Администратор может создавать, редактировать и удалять товары.

Создание товара

Форма содержит:

название;
категорию;
цену;
количество;
изображение;
краткое описание;
подробное описание;
характеристики.

Характеристики добавляются динамически в формате:

Название характеристики → Значение

Например:

DPI → 26000
Вес → 72 г
Подключение → Wireless
Редактирование

Администратор может изменить:

название;
категорию;
цену;
количество;
изображение;
описания;
характеристики.
Удаление

Перед удалением товара система запрашивает подтверждение.

Удаление товара не должно приводить к потере информации о товаре в уже существующих заказах.

15. Управление категориями

Администратор может:

создавать категории;
редактировать категории;
удалять категории.

Удаление категории, содержащей товары, должно быть защищено от потери связанных данных.

16. Управление заказами

Администратор видит список заказов.

Для каждого заказа отображаются:

номер;
дата;
покупатель;
сумма;
статус.

Администратор может открыть заказ и увидеть:

контактные данные;
состав;
количество;
цены;
итоговую стоимость;
комментарий.

Администратор может изменить статус заказа.

При переводе заказа из NEW в CONFIRMED выполняется повторная проверка наличия товаров и списание остатков.

17. Уведомления в Telegram

При создании нового заказа система отправляет уведомление администратору через Telegram Bot API.

Уведомление содержит:

номер заказа;
имя покупателя;
контактные данные;
список товаров;
количество;
сумму заказа;
дату создания.

Telegram используется как дополнительный канал уведомления и не заменяет отображение заказов в административной панели.

18. Обработка ошибок

Система должна обрабатывать:

недоступность товара;
недостаточное количество товара;
удаление товара после добавления в корзину;
ошибки загрузки каталога;
ошибки создания заказа;
ошибки авторизации;
неправильные данные формы;
потерю соединения.

Критические операции обязательно дополнительно проверяются на сервере.

Клиентской валидации недостаточно.

19. Адаптивность

Интернет-магазин должен корректно работать на:

Desktop;
Tablet;
Mobile.

Минимальная поддерживаемая ширина — 320px.

Не допускается:

горизонтальный скролл страницы;
перекрытие элементов;
выход текста за пределы контейнеров;
некорректное отображение карточек;
недоступность элементов управления.

Корзина и административная панель должны иметь адаптированное мобильное представление.

Распределение:

23. Ограничения MVP

В первую версию не входят:

онлайн-оплата;
интеграция с платёжными системами;
доставка;
интеграция с транспортными компаниями;
полноценная система отзывов;
рейтинги товаров;
программа лояльности.

Архитектура должна позволять добавить эти функции в будущем.

24. Визуальное направление

Интерфейс должен быть современным, чистым и ориентированным на интернет-магазины компьютерной техники.

Основные принципы:

минималистичный интерфейс;
акцент на товарах;
хорошо читаемая типографика;
понятная иерархия информации;
заметные CTA-кнопки;
аккуратные карточки товаров;
единообразные иконки;
адаптивный дизайн;
поддержка светлой и тёмной темы не является обязательным требованием MVP, если она не будет включена в отдельное дизайн-ТЗ.

Конкретные цвета, размеры, типографика, компоненты и визуальные правила будут определены отдельно в Design.md.
