# План разработки проекта TechGear (development-plan.md)

Настоящий документ содержит последовательный, логически упорядоченный план реализации интернет-магазина компьютерной техники и аксессуаров **TechGear** на основе требований [TZ.md](file:///c:/Users/User/Desktop/internetMagazine_AI/docs/TZ.md). 

Развитие проекта разделено на два этапа: сначала разрабатывается клиентская визуальная часть (Frontend), затем реализуется серверная логика и база данных (Backend & Database).

---

## 🎨 Этап 1. Frontend-задачи (Интерфейс и клиентская логика)

Каждый шаг этого этапа подготавливает страницы и компоненты согласно [Design.md](file:///c:/Users/User/Desktop/internetMagazine_AI/Design.md), используя заглушки для получения данных.

### 1. Глобальный макет (Layout) и навигация
* Верстка шапки сайта (Header) с поисковой строкой, ссылками на профиль, корзину и тонкими информационными полосами.
* Верстка подвала сайта (Footer) с контактными данными и структурированными ссылками.
* Реализация панели категорий (Category Bar) под хедером в виде горизонтального прокручиваемого списка капсул.
* Создание Zustand-хранилища для корзины с механизмом сохранения состояния в `localStorage` (для гостевого режима).

### 2. Главная страница и каталог товаров (`/`)
* Верстка Hero-промо-баннера с ярким градиентным фоном и кнопкой призыва к действию.
* Верстка адаптивной сетки карточек товаров (изображение, название, бренд, цена шрифтом Mono, статус наличия, кнопка добавления в корзину).
* Реализация логики переключения категорий и отображения статуса «Нет в наличии» на карточке товара.
* Верстка бокового сайдбара фильтрации (по категориям, ценам, брендам, типу подключения).

### 3. Детальная страница товара (`/product/[slug]`)
* Верстка страницы товара: двухколоночный макет (галерея изображений слева, конфигуратор покупки справа).
* Верстка таблицы технических характеристик товара.
* Реализация селектора количества товара (с ограничением по остатку на складе).
* Интеграция кнопки добавления товара в локальную Zustand-корзину.

### 4. Виджет корзины (Cart Drawer)
* Верстка выдвижной боковой панели корзины (компонент Sheet из shadcn/ui) с размытием фона.
* Реализация списка элементов корзины с отображением миниатюр картинок, названий и цен.
* Реализация интерактивных кнопок изменения количества (`+` / `-`), кнопок удаления товара и автоматического пересчета итоговой стоимости.
* Добавление кнопки перехода к оформлению заказа.

### 5. Страницы авторизации и регистрации (`/login`, `/register`, `/reset-password`)
* Верстка формы регистрации покупателя (Имя, Email, Пароль, Подтверждение пароля) с клиентской валидацией React Hook Form + Zod.
* Верстка формы входа (Email, Пароль) с ссылками на регистрацию и сброс пароля.
* Верстка интерфейса восстановления доступа (запрос ссылки на email и установка нового пароля).

### 6. Оформление заказа (Checkout)
* Верстка страницы формы оформления заказа (Имя, Фамилия, Email, Телефон, Комментарий к заказу).
* Реализация подстановки данных из профиля пользователя (для авторизованных покупателей).
* Верстка страницы успешного создания заказа.

### 7. Личный кабинет покупателя (`/account`, `/account/orders/[id]`)
* Верстка раздела профиля пользователя с возможностью изменения персональных данных (имя, фамилия, телефон, email).
* Верстка истории заказов в виде таблицы (номер, дата, сумма, статус-бейдж).
* Верстка детальной страницы заказа с полным составом позиций и кнопкой самостоятельной отмены заказа (доступной только для статуса `NEW`).

### 8. Административная панель (`/admin`)
* Верстка разметки админки с боковой навигацией (Dashboard, Товары, Категории, Заказы).
* Раздел категорий: таблица категорий с кнопками добавления, редактирования и удаления.
* Раздел товаров: форма создания/редактирования товара с динамическим добавлением строк характеристик (Название характеристики → Значение) и загрузкой картинок.
* Раздел заказов: таблица всех заказов с детальным просмотром контактных данных покупателя, состава позиций и селектором изменения статуса заказа.

## 🗄️ Этап 2. Backend и Database задачи (База данных и серверная логика)

На этом этапе создаются сущности БД, связываются с фронтендом через Server Actions/Route Handlers и реализуются требования [SECURITY.md](file:///c:/Users/User/Desktop/internetMagazine_AI/SECURITY.md).

### 9. Проектирование базы данных и ORM (Prisma)
* Описание моделей базы данных в `prisma/schema.prisma` согласно разделу 21 ТЗ (`User`, `Category`, `Product`, `Cart`, `CartItem`, `Order`, `OrderItem`, `PasswordResetToken`).
* Описание связей и ограничений внешних ключей (каскадное удаление корзины, nullable связь товара в заказах для безопасного удаления).
* Инициализация клиента Prisma в виде глобального синглтона.

### 10. Наполнение тестовым каталогом (Seed)
* Написание скрипта `prisma/seed.ts` для автоматического создания дефолтных категорий и первоначального каталога из 18–20 товаров с реалистичными характеристиками для тестов.

### 11. Модуль авторизации и восстановления доступа
* Настройка Auth.js (NextAuth) для управления сессиями и хранения ролей (`CUSTOMER` / `ADMIN`) в JWT-токенах.
* Реализация бэкенд-валидации регистрации с хешированием пароля (`bcryptjs`) и проверкой уникальности email.
* Создание серверного действия сброса пароля: генерация безопасного одноразового токена `PasswordResetToken`, отправка ссылки на email через SMTP и валидация токена при установке нового пароля.

### 12. CRUD категорий и товаров (Админка)
* Реализация Server Actions для управления категориями (с проверкой роли `ADMIN` и валидацией запрета удаления категорий с активными товарами).
* Реализация Server Actions для товаров с поддержкой **Soft Delete** (заполнение `deletedAt` вместо физического удаления, если товар фигурирует в заказах).
* Подключение загрузки изображений товаров на стороне сервера и их отправки в облачное хранилище **Cloudinary**.

### 13. Управление корзиной на сервере
* Создание Server Actions для добавления, изменения количества и удаления товаров в базе данных для авторизованных пользователей.
* **Реализация алгоритма слияния корзин (Merge):** при авторизации гостевые элементы из Zustand передаются на сервер, суммируются с БД-корзиной (с учетом проверки актуальных цен и остатков на складе), а локальный стейт очищается.

### 14. Механизм создания заказов
* Реализация Server Action `createOrder` (валидация данных Zod, получение цен товаров из БД, проверка остатков на складе).
* Инициализация транзакции `prisma.$transaction` для атомарной записи заказа, создания `OrderItem` (копирование названий и цен на момент покупки) и очистки корзины в БД.

### 15. Логика списания остатков и отмены заказов
* Реализация транзакции изменения остатков на складе при переводе заказа администратором из `NEW` в `CONFIRMED` с атомарным декрементом и блокировкой строки товара (`stock: { gte: quantity }`).
* Реализация бизнес-правил отмены: изменение статуса заказа на `CANCELLED` без физического удаления.
* Обработка ошибок нехватки остатков и возврат безопасных сообщений администратору.

### 16. Сервис уведомлений в Telegram
* Интеграция с Telegram Bot API: формирование HTML-сообщения с деталями нового заказа (номер, покупатель, состав, сумма).
* Настройка асинхронной отправки сообщений в групповой чат администраторов без блокирования ответа пользователю.
