# План разработки проекта TechGear (development-plan.md)

Настоящий документ содержит последовательный, логически упорядоченный план реализации интернет-магазина компьютерной техники и аксессуаров **TechGear** на основе требований [TZ.md](file:///c:/Users/User/Desktop/JS+AI_deep_course/internetMagazine_AI/docs/TZ.md).

Развитие проекта разделено на три этапа: клиентская визуальная часть (Frontend), серверная логика и база данных (Backend & Database), а также системные сквозные модули (мультивалютность, локализация, SEO, настройки и тестирование).

## 🗄️ Этап 2. Backend и Database задачи (База данных и серверная логика)

На этом этапе созданы сущности БД, связаны с фронтендом через Server Actions/Route Handlers и реализованы требования [SECURITY.md](file:///c:/Users/User/Desktop/JS+AI_deep_course/internetMagazine_AI/SECURITY.md).

### 9. Проектирование базы данных и ORM (Prisma) `[x]` (COMPLETED)
* Описание моделей базы данных в `prisma/schema.prisma` согласно разделу 21 ТЗ (`User`, `Category`, `Product`, `Cart`, `CartItem`, `Order`, `OrderItem`, `PasswordResetToken`, `SystemSetting`).
* Описание связей и ограничений внешних ключей (каскадное удаление корзины, nullable связь товара в заказах для безопасного удаления).
* Инициализация клиента Prisma в виде глобального синглтона.

### 10. Наполнение тестовым каталогом (Seed) `[x]` (COMPLETED)
* Написание скрипта `prisma/seed.ts` для автоматического создания дефолтных категорий, первоначального каталога товаров с реалистичными характеристиками, тестовых пользователей и начальных настроек магазина.

### 11. Модуль авторизации и восстановления доступа `[x]` (COMPLETED)
* Настройка Auth.js (NextAuth) для управления сессиями и хранения ролей (`CUSTOMER` / `ADMIN`) в JWT-токенах.
* Реализация бэкенд-валидации регистрации с хешированием пароля (`bcryptjs`) и проверкой уникальности email.
* Создание серверного действия сброса пароля: генерация безопасного одноразового токена `PasswordResetToken`, отправка ссылки на email через SMTP и валидация токена при установке нового пароля.

### 12. CRUD категорий и товаров (Админка) `[x]` (COMPLETED)
* Реализация Server Actions для управления категориями (с проверкой роли `ADMIN` и валидацией запрета удаления категорий с активными товарами).
* Реализация Server Actions для товаров с поддержкой **Soft Delete** (заполнение `deletedAt` вместо физического удаления, если товар фигурирует в заказах).
* Подключение защищённой загрузки изображений товаров на стороне сервера и их стриминговой отправки в объектное хранилище **Backblaze B2** (S3-compatible API via `@aws-sdk/client-s3`) с валидацией MIME-типов, расширений и лимита размера (5 МБ), а также поддержка прямого ввода внешних URL.

### 13. Управление корзиной на сервере `[x]` (COMPLETED)
* Создание Server Actions для добавления, изменения количества и удаления товаров в базе данных для авторизованных пользователей.
* **Реализация алгоритма слияния корзин (Merge):** при авторизации гостевые элементы из Zustand передаются на сервер, суммируются с БД-корзиной (с учетом проверки актуальных цен и остатков на складе), а локальный стейт очищается.

### 14. Механизм создания заказов `[x]` (COMPLETED)
* Реализация Server Action `createOrder` (валидация данных Zod, получение цен товаров из БД, проверка остатков на складе).
* Инициализация транзакции `prisma.$transaction` для атомарной записи заказа, создания `OrderItem` (копирование названий и цен на момент покупки) и очистки корзины в БД.

### 15. Логика списания остатков и отмены заказов `[x]` (COMPLETED)
* Реализация транзакции изменения остатков на складе при переводе заказа администратором из `NEW` в `CONFIRMED` с атомарным декрементом и блокировкой строки товара (`stock: { gte: quantity }`).
* Реализация бизнес-правил отмены: изменение статуса заказа на `CANCELLED` без физического удаления.
* Обработка ошибок нехватки остатков и возврат безопасных сообщений администратору.

### 16. Сервис уведомлений в Telegram `[x]` (COMPLETED)

## 🌐 Этап 3. Системные и сквозные модули (Реализованные расширения)

### 17. Мультивалютность и автоматическая синхронизация курсов валют `[x]` (COMPLETED)
* Модель `SystemSetting` в БД для персистентного хранения курса (USD/UZS), даты обновления и источника курса.
* Сервис `ExchangeRateService` с интеграцией API Центрального банка Республики Узбекистан (CBU API) для получения официального курса USD.
* Фоновый эндпоинт `/api/cron/exchange-rate` для периодического автоматического обновления курса и возможность ручной синхронизации администратором (`/admin/settings`).
* Компонент `CurrencySwitcher`, пересчет цен (USD ↔ UZS) по всему приложению, а также локализованное форматирование валют с учетом активной локали (`Intl.NumberFormat`).

### 18. Интернационализация (i18n) и URL-based навигация `[x]` (COMPLETED)
* Маршрутизация на основе динамического сегмента `/[locale]` для 3 языков: русский (`ru`), узбекский (`uz`), английский (`en`).
* Next.js Middleware/Proxy с автоматическим определением локали (cookie `NEXT_LOCALE` / заголовок `Accept-Language`), редиректами и сохранением query-параметров поиска и фильтрации.
* Синхронизированные JSON-словари переводов (`src/i18n/dictionaries/{ru,uz,en}.json`) и серверно-клиентский доступ к переводам (`getDictionary`, `useTranslations`).
* Компоненты переключения языка (`LanguageSwitcher`) в шапке, подвале, формах аутентификации и чекаута.

### 19. Поисковая оптимизация (SEO) и метаданные `[x]` (COMPLETED)
* Утилиты SEO (`src/lib/seo.ts`): генерация канонических URL, локализованных `hreflang` alternates для всех 3 языков (`x-default` -> `ru`), OpenGraph и Twitter Cards.
* Динамическая генерация метаданных (`generateMetadata`) для главной страницы, каталога, страниц категорий и детальной карточки товара `/[locale]/product/[slug]`.
* Динамические маршруты `src/app/robots.ts` (`/robots.txt`) и `src/app/sitemap.ts` (`/sitemap.xml`) с автоматическим перечислением всех активных категорий и товаров по всем локалям.
* Защита приватных разделов (`/admin/*`, `/[locale]/account/*`, `/[locale]/checkout/*`, `/[locale]/login`, `/[locale]/register`, `/[locale]/reset-password`) от индексации поисковыми системами (`robots: { index: false, follow: false }`).

### 20. Управление параметрами магазина и витриной (Shop Settings) `[x]` (COMPLETED)
* Раздел общих настроек магазина в панели администратора (`/admin/settings`): контактные телефоны, email поддержки, физический адрес, часы работы, стоимость и порог бесплатной доставки.
* Управление статусом «Популярный товар» (`isPopular`) в форме товара для динамического размещения в Hero-баннере главной страницы и акцентных блоках каталога.

### 21. Комплексное автоматизированное тестирование `[x]` (COMPLETED)
* Модульное и интеграционное тестирование на **Vitest** (26 тестовых файлов, 180 тестов), покрывающее Server Actions, Zustand-корзину, валидацию Zod, утилиты валют, B2-загрузку, i18n и SEO.
