# Правила безопасности TechGear (security-rules.md)

Данный документ содержит ключевые требования и инварианты безопасности для ИИ-агентов и разработчиков при изменении и расширении функционала проекта **TechGear**.

---

## 🔒 Ключевые инварианты безопасности

1. **Принцип нулевого доверия к клиенту:**
   * Любые данные, полученные от клиента (параметры, тела Server Actions, FormData, заголовки, куки), считаются недоверенными и подлежат повторной валидации на сервере.
   * Клиент никогда не передает цены товаров (`price`) или итоговые суммы заказов (`totalAmount`). Эти значения извлекаются и рассчитываются сервером на основе доверенных данных из базы данных.

2. **Серверная проверка полномочий:**
   * Вся проверка сессий (`auth()`) и ролей (`ADMIN`, `CUSTOMER`) должна выполняться строго на сервере. Скрытие кнопок или элементов UI не является мерой защиты.
   * Пользователи с ролью `CUSTOMER` не имеют доступа к операциям под ролью `ADMIN` (CRUD товаров/категорий, изменение статусов любых заказов).
   * Покупатель (`CUSTOMER`) может работать только с собственным профилем и историей заказов. Отменить заказ покупатель может только самостоятельно и только в статусе `NEW`.

3. **Валидация данных:**
   * Все параметры Server Actions и Route Handlers должны парситься схемами Zod (whitelist-подход). Не полагаться на типы TypeScript или HTML5-валидацию клиента.
   * Числовые значения (количества, цены) должны быть положительными (`> 0`). Длина строк (имена, email, комментарии) должна быть ограничена.

4. **Работа со складом и транзакции:**
   * Списание товаров со склада происходит только при переводе заказа в статус `CONFIRMED` администратором.
   * Операция списания должна быть защищена от race conditions (атомарное уменьшение с проверкой `stock: { gte: quantity }` в транзакции базы данных Prisma).

5. **Защита от утечки секретов:**
   * Строго запрещено хардкодить пароли, ключи API, токены (Telegram, Cloudinary) или реквизиты СУБД в коде.
   * Переменные окружения должны загружаться через `process.env`. Локальный файл `.env` должен быть в `.gitignore`.
   * ИИ-агент не должен раскрывать реальные значения секретов в ответах или промптах.

6. **Аутентификация и сессии:**
   * Хранение паролей выполняется исключительно в хешированном виде (`bcryptjs`).
   * Сессионные токены (JWT) Auth.js хранятся только в безопасных `httpOnly` куках с флагами `Secure` и `SameSite=Lax`. Хранить их в `localStorage` запрещено. При этом хранение нечувствительного состояния (гостевая корзина) в `localStorage` разрешено.
   * Ссылка на сброс пароля отправляется в виде одноразового токена со сроком жизни 1 час.

7. **Загрузка файлов:**
   * Загрузка изображений товаров выполняется через серверное действие с валидацией размера (до 5 МБ), MIME-типа и расширения (только безопасные изображения) с последующим экспортом в Cloudinary.

8. **Обработка ошибок:**
   * Запрещено отдавать клиенту stack trace, системные сообщения Prisma или детали структуры базы данных. Клиент должен получать безопасные обобщенные сообщения (`ActionResult`).
